## Coverage and provenance questions

1. **Historical roster.** Can you supply a complete as-issued NQ definition baseline and all deltas for each row, or a venue-certified equivalent? Identify file/SKU, channel, replay loop completeness, dates, as-issued versions and original dissemination times. Include SecurityID and dated raw symbol, security type/group, expiry, activation and last eligible trade, add/modify/delete records, and zero-print instruments. Can you distinguish preannounced, disseminated, effective and removed listings? State whether a next-day flat file or historical snapshot was rebuilt.
2. **Volume semantics.** Can you supply timestamped MDP Electronic Volume (`MDEntryType=e`) by SecurityID, or a demonstrably equivalent as-issued ledger? Specify cumulative or incremental units, reset and carry-over across each split date, initial state and recovery, spread legs and implied trades, and handling of blocks, ClearPort and other off-book activity. Explain how the quantity differs from Trade Summary, normalized outright `trades`, OHLCV volume and cleared volume. If quoting print data, describe the exact metric it can reproduce and which event types it omits. What evidence establishes a true zero per candidate and segment?
3. **Timestamps.** For every file and message class, identify the original fields for exchange event/effective time, exchange packet send, provider capture and gateway send. Give capture location, precision, accuracy, synchronization, sequence/tie behavior, known substitutions, backfill and replay flags, and which clock indexes request bounds. For predecessor `ohlcv-1m`, can you attest to retention of the original first-emitted payload, version and gateway time with later reissues? Quote the last predecessor minute per cutoff and its publication/revision records through the diagnostic end only as a separate boundary-evidence option. Give the smallest exportable interval and any version linkage or original capture limits. State explicitly if only current historical bars or inbound capture survive. [Databento clock conventions](https://databento.com/docs/conventions/common-fields-enums-types)
4. **Corrections and recovery.** Which files retain originals plus inserts, breaks, cancels, changes, late reports, sequence recovery and historical repairs? Specify IDs linking an affected record to its replacement, effective time and first dissemination/capture of each change. Can a reviewer reconstruct the earlier state after later corrections or normalization changes? Provide schema/template and normalization versions effective on these dates. Identify revisions later than the quoted windows in metadata where available, and quote original version or correction evidence beyond those bounds separately if needed.
5. **Schedule, status and completeness.** Can you supply dated NQ-specific calendars or a dated Equities-to-NQ mapping, revisions, and actual Security Status with initial state, halts, reopens and trade-date resets? For each window and required channel/message type, give exact covered intervals, packet and instrument sequences, capture gaps, duplicated feeds, recovery completeness, known omissions and any unrecoverable ranges. Distinguish verified no-activity intervals from missing data. Specify whether completeness is certified, inferred or unknown and provide evidence lineage, request metadata and file checksums with any eventual delivery.
6. **Licensing.** Identify vendor and exchange permissions, all fees and any restrictions on historical non-display research, secure retention of original bytes, schema and evidence snapshots, backup, reproducibility by an independent reviewer, and distribution of hashes, derived coverage totals or excerpts. Specify access or licensing required for a second reviewer and retention/deletion obligations.
7. **Price and delivery.** Quote separately for (a) normalized definitions/status/trades, (b) timestamped Electronic Volume or equivalent, (c) raw PCAP with definition replay/status/recovery plus dated decoding materials, (d) calendar/version evidence, and (e) original outbound publication evidence. For each option report required channel/date minimums, quote boundaries and pricing inputs, bytes, one-time/recurrent exchange and license fees, export/retrieval/egress fees, applicable taxes, estimated delivery and quote expiry. Separate verified coverage from unconfirmed catalog availability. List unsupported items and comparable alternatives with their precise limitations.
